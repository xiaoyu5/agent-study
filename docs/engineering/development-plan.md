# 开发计划：以学习为目的逐步实现

当前目标：完成 M0 的范围、规范和可运行基础骨架。后续每次推进一个可演示增量；每个阶段都解释设计原因、观察失败、记录验收结果，不一次生成完整产品。

## 阶段与验收

| 阶段 | 学什么 | 实现什么 | 如何验收 |
| --- | --- | --- | --- |
| M0 准备 | 领域建模、内容与运行时分离、协作 | 首课范围、Git/角色规范、课程 JSON、离线校验 CLI | 正常课程可读；坏引用/环等被拒绝；明确草稿状态 |
| M1 最小 Agent | 对应上游 s01–s02：消息、工具调用与回传 | 一个模型接口、脚本模型、一个只读课程工具、有上限的循环；再接一个真实模型 | 脚本轨迹可复现；调用 ID 配对；未知工具与达到上限有明确结果；真实模型最小演示另行记录 |
| M2 教学闭环 | 业务规则如何约束模型；对应 s03–s04 | 诊断、解释、提示、作答与独立检查；确定性贝叶斯计算 | 真实首答与提示被记录；辅助成功不冒充独立成功；错误公式和错误条件被识别 |
| M3 会话可靠性 | 状态、持久化、预算、上下文；参考 s08/s10 | 恢复同版本课程、取消、运行日志和上下文管理 | 中断恢复保留作答；预算退出不是毕业；损坏状态有明确处理 |
| M4 迁移与评估 | 学习结果评估、模型评分的局限 | 未见题、领域映射、rubric、保留评估集、人工复核 | 可定位每条结论的证据；缺数据题不编数字；报告工程与学习指标 |
| M5 小范围试点 | 可用性与实际交付 | 适合普通人的轻量界面、会话隔离、导出/删除记录、运行说明 | 目标用户可以完成一节课；保存失败、退出与反馈，不夸大教学效果 |

课程包、题目和评分标准须与代码同样评审。在 M2 实现前建立已核验例题和标准答案；在 M4 开始前冻结保留题。M5 的界面选择基于前面试用情况，不预先决定前端栈。

## 每个任务的学习节奏

1. Lead 说明要解决的真实问题，阅读相关上游章节的最小部分。
2. 人类 Lead 尝试用自己的话解释机制；可先写伪代码或做一个小练习。
3. AI Develop 实现约定范围内的小增量，说明关键设计和可替代方案。
4. 演示一个成功路径与一个真实失败边界；测试针对行为，不堆砌实现细节。
5. AI Lead 做代码与证据评审，人类 Lead 审核学习目标和重要取舍。
6. 按 [协作规范](collaboration.md) 留交接，再按 [Git 规范](git-workflow.md) 集成。

## 本轮运行方式

在仓库根目录、Python 3.11+ 环境运行：

```sh
PYTHONPATH=src python3 -m education_agent validate-course courses/bayes-intro/course.json
PYTHONPATH=src python3 -m education_agent inspect-course courses/bayes-intro/course.json
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

这三条命令不使用模型、不发网络请求、不要求 API key。它们只验证 M0，不能作为未来 Agent 或学习效果的验收证据。后续添加 SDK 时再建立锁定依赖和 CI。

## 完成条件

一个开发任务只有在范围内实现、必要验证通过、文档同步、交接齐全并按规范集成后才标记 done。M0 的“可运行”指课程检查入口可运行；课程草稿尚未变成人工审核的教材，学习 Agent 尚未完成。
