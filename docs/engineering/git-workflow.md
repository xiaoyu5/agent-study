# Git 分支与集成规范

状态：项目协作基线草案。首课为概率与决策／贝叶斯思维，技术栈为 Python。
本文描述执行约定；尚未配置或验证远端分支保护、CI、自动评审与合并权限。

## 1. 分支与任务边界

- `main` 保存已验收、可运行的阶段成果；每个阶段都能说明学到了什么。
- 使用短期分支 `codex/<task-id>-<slug>`，例如 `codex/edu-001-lesson-contract`。
- `Develop` 是 AI 开发角色，不建立长期 `develop` 分支。
- 独立写任务默认对应一个分支、一个 worktree、一个主要写入者。
- 同一任务内，工具限制子代理共享目录时，Lead 可分配互不重叠的写入路径；共享文件与 Git 写操作由 Lead 独占并统一集成。本轮 M0 采用此方式，它是路径分工，不是 worktree 隔离。
- 只读审查可共享工作区；写任务依赖相同接口时，先合并接口约定，再从该版本分叉。
- 不把其他任务的未提交修改、密钥、学习者个人资料或本地运行记录纳入提交。

## 2. 开始任务

先在任务卡登记范围、允许修改路径、依赖和验收命令，参见[协作规范](collaboration.md)。
以下命令是操作示例，未在本次文档编写中执行。替换任务编号、名称与路径；路径必须可写且尚不存在。

```sh
git status --short --branch
git worktree list
git log -1 --oneline main
git worktree add -b codex/edu-001-lesson-contract ../agent-study-edu-001 main
```

有远端时先检查 `git remote -v`，再按实际远端名称获取更新并确认基线。
仅在干净的 `main` 工作区中使用 `git pull --ff-only`；尚无远端时直接以本地已确认的 `main` 为基线。
遇到本地修改、分支不存在或分叉情况，先报告状态并保留现场，不使用强制参数覆盖。

## 3. 实现与提交

- 小步提交，每次围绕一个可解释的目的；推荐 `类型(任务号): 结果`，例如 `feat(edu-002): validate lesson references`。
- 提交前检查 `git diff` 和 `git diff --check`，按明确路径暂存，再检查 `git diff --cached`。
- 任务内可自主编辑、调试、运行验证；提交、推送与合并按该任务已有授权执行，不为每个可逆步骤重复询问。
- 不改写他人提交，不使用 `reset --hard`、`clean -fd`、强制推送或强制删除来解决协作冲突。
- 同步主干时先保证工作区干净；默认合并 `main` 到任务分支并解决冲突，避免改写已共享历史。
- 冲突解决后重跑受影响的验收；涉及需求、课程结论或评分标准的冲突交由 Lead 决策。

## 4. 提交审查

PR 或本地审查记录均可作为载体；没有远端时不虚构 PR 链接。
说明应包含：问题与目标、最终行为、文件范围、验收结果、学习收获、限制、回退办法。
第一阶段为本地课程查看与校验，不应把尚未实现的模型调用或 Agent loop 写为已交付。

基础验收在项目根目录运行，环境按开发文档配置：

```sh
PYTHONPATH=src python3 -m unittest discover -s tests -v
git diff --check
```

还须执行任务卡列明的功能命令；记录工作目录、Python 版本、提交 SHA、命令、退出码和关键结果。
没有运行的检查标明“未运行”及原因；不能以“应该通过”代替证据。

## 5. 合并条件

合并前同时具备以下证据，详见[协作规范](collaboration.md)：

1. 人类 Lead：需求、学习价值和重要取舍的明确审核记录，可引用仍适用的已批准任务或批次。
2. Lead AI：对当前待合并 SHA 的技术审查与验收结果；Develop 的自检不能替代独立审核。

任务保持 `ready_for_review` 或 `in_review`，直到阻塞问题消除。审查后修改代码或课程内容，需重新检查受影响部分。
人类 Lead 既有批准可在范围未变时复用；变更需求、首课目标、评估标准或重要架构取舍须重新审核。
由获授权的集成者合并，默认保留可追踪的普通合并历史；执行后记录合并 SHA 并运行约定的主干验收。
只有成果已进入 `main`、验收通过且交接完成，任务才为 `done`。

## 6. 清理与回退

确认已合并、工作区无未提交修改、交接记录已保存后，才在其他工作区执行清理：

```sh
git worktree remove ../agent-study-edu-001
git branch -d codex/edu-001-lesson-contract
```

若命令拒绝执行，先核对状态，不加 `--force` 或 `-D` 绕过检查。
若另行采用 squash，`-d` 可能拒绝删除；确认等价改动及保存方式后再单独处理，不自动强删。
已共享的错误通过新的 `git revert` 提交回退；合并提交须确认父分支和 `-m` 参数，由集成者执行。
回退后记录受影响版本和原因，并重跑相关验收；不得静默改变历史评测结果。
